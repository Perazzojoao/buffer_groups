*buffer_groups.txt*  Two editor groups with independent buffer navigation

==============================================================================
OVERVIEW                                                   *buffer_groups*

Requires Neovim >= 0.11. No runtime dependencies. Core management supports two
independent groups per tabpage; different tabpages have independent state. One
normal group exists before partitioning. Listed unloaded buffers remain
available. Bufferline and Snacks are optional. The native multi-group winbar
requires the Bufferline 4.9.1 adapter.

INSTALLATION                                              *buffer_groups-install*

Register the published release with vim.pack, then configure the plugin: >lua
  vim.pack.add({
    { src = 'https://github.com/Perazzojoao/buffer_groups', version = 'v0.3.0' },
  })
  require('buffer_groups').setup({
    keymaps = { move_left = '<leader>h', move_right = '<leader>l',
                previous = '<A-h>', next = '<A-l>',
                close_group = '<leader>kg', close_others = '<leader>ko',
                toggle_fullscreen = '<leader>mm' },
  })
<
The plugin does not require vim.pack; other package managers can load the same
repository and call setup(). For local development, prepend a checkout instead
of adding a package entry: >lua
  vim.opt.runtimepath:prepend(vim.fn.expand('~/Dev/Personal/buffer_groups'))
  require('buffer_groups').setup({})
<
For a manual runtimepath installation, generate the help index once with
:helptags ~/Dev/Personal/buffer_groups/doc.

==============================================================================
OPTIONS                                              *buffer_groups.setup()*

setup({opts}) is idempotent. No default keymaps. Available mapping names:
move_left, move_right, previous, next, close, close_group, close_others,
reorder_left, reorder_right, toggle_fullscreen, toggle_winbar, toggle_tabs,
toggle_tabline_groups
(normal mode).

Reordering is available starting with v0.3.0. reordering.enabled=false by
default. Reordering has no default keymaps. Set
reordering.enabled=true and configure keymaps.reorder_left/reorder_right to
choose mappings. <A-H>/<A-L> represent Shift-Alt-H/L; existing <A-h>/<A-l>
mappings can continue cycling within the focused group. For example: >lua
  require('buffer_groups').setup({
    reordering = { enabled = true },
    keymaps = { reorder_left = '<A-H>', reorder_right = '<A-L>' },
  })
  local adapter = require('buffer_groups.integrations.bufferline')
  local config = adapter.extend({ options = { mode = 'buffers' } },
                              { managed_order = true })
  require('bufferline').setup(config)
  adapter.attach()
<
Core enable()/disable() activates or suspends the configured feature with the
other mappings/observers.

exclude.floating=true is required: only normal windows can own layout groups.
exclude.unlisted=true; default filetypes are snacks_layout_box/snacks_picker_list;
default buftypes are nofile/help/terminal/quickfix/prompt. Lists replace defaults.
exclude.bufname is a list of Lua name patterns. exclude.window/exclude.buffer
are predicates receiving {win,buf,tabpage}; true excludes. Hidden buffers can
have win=nil. Any matching exclusion wins.

behavior.follow_buffer=true
behavior.empty_group='close'
behavior.existing_buffer='focus_owner' ('transfer' also supported)
behavior.single_buffer_split='require_two' ('new_buffer' also supported)
behavior.manual_window_close='merge'
closing.last_buffer='empty' ('quit' also supported)
closing.save_others=false (save modified targets before close_others)
tabline.show_groups=true (boolean; hide the group controls with false)

Initialize with two eligible buffers; otherwise leave layout unchanged. Existing
pairs are adopted. More than two eligible windows prevents initialization.
Stacked pairs become side by side; existing editor IDs and sidebars are kept.
Moving buffers appends to the destination list and removes source membership;
empty source closes. Manual window close merges into the surviving group.
Unsaved changes are preserved by moving; close requires explicit force to
discard them. Rename/unload keep ownership. Auxiliary views remain excluded.

close_group() checks all members for unsaved changes before deleting any, then
closes the focused group. force=true explicitly discards modifications. The last
group follows closing.last_buffer; 'empty' keeps a new editable replacement when
the final editor window is required. Closing the visible fullscreen group first
reveals the other group.

close_others() closes all other members of the focused group, keeping its current
buffer, split and fullscreen state. Other groups are unaffected. A one-buffer
group succeeds with an empty list. Unsaved changes are refused by default.
closing.save_others=true or save=true saves all modified targets before deleting
any. A write failure keeps all buffers open; earlier writes may already be saved.
The current buffer is never saved. force=true skips automatic saving and discards
modifications; explicit save=true still requests saving even when forced.

toggle_fullscreen() expands the focused group into the editing area; its
partner's split is hidden without deleting buffers. With one group it returns
true,false without changing the layout. Extra eligible editing splits cause an
error; fullscreen needs the two initialized groups to be the only editor windows.
Another call restores the split and its displayed buffer. Excluded sidebars stay
in place. Moving into the hidden group or opening its buffer with focus_owner
reveals it. New files and local cycling continue in the visible group.

==============================================================================
API                                                    *buffer_groups-api*

require('buffer_groups') exposes:
  move('left'|'right', {buf?,win?,tabpage?,group?})
  cycle(1|-1)
  reorder(-1|1, {win?,tabpage?,from_index?})
  reorder_to(index, {win?,tabpage?,from_index?})
  open(bufnr, {win?,tabpage?,group?,focus?})
  register(bufnr, {win?,tabpage?,group?})
  close(bufnr, {force?,tabpage?})
  close_group({win?,tabpage?,group?,force?})
  close_others({win?,tabpage?,group?,save?,force?})
  toggle_fullscreen({win?,tabpage?})
  get_state({tabpage?})
  get_owner(bufnr, {tabpage?})
  set_winbar_enabled(boolean), is_winbar_enabled()
  set_group_tabs_visible(boolean, {group_id?,tabpage?})
  toggle_group_tabs({group_id?,tabpage?})
  set_tabline_groups_visible(boolean), toggle_tabline_groups()
  get_tabline_options()
  get_reordering_options(), is_reordering_enabled()
  enable(), disable(), is_enabled()

Mutations return true,result or false,error. Commands report errors. Queries
return defensive copies. State:
{enabled,tabpage,active,fullscreen,focused,winbar_enabled,groups,owners}.
Group: {id,win,side,buffers,current,hidden,tabs_visible}. Side:
left/right/single. Stable group IDs identify ownership independently of spatial
positions.
Hidden groups have win=nil; restored splits receive new window IDs. Read fresh
snapshots when resolving destinations. close_group/close_others return closed buffer IDs;
toggle_fullscreen returns the new fullscreen boolean.

reorder() swaps the current buffer with the adjacent member of its owning
group. It does not wrap at group edges; an edge move succeeds with moved=false.
reorder_to(index) swaps with the buffer at the one-based group position; a
negative index counts from the end. from_index optionally chooses the source
position in that group. Successful
changes return {buf,group_id,from,to,moved}; invalid zero/non-integer indices
and zero target indices return false,error; delta 0 is a successful no-op.
get_reordering_options() returns a copy of the configured options, and
is_reordering_enabled() reports whether the feature is currently active.
Reordering only changes session state and does not publish or persist order.

disable() reveals hidden groups, preserves buffers and restores owned mappings only if
the current mapping is still installed by the plugin. enable() starts fresh
tracking; split initialization remains lazy.

==============================================================================
COMMANDS                                                *:BufferGroupsMove*

:BufferGroupsMove left|right    Initialize or transfer buffer to side.
:BufferGroupsNext              Cycle forward in the focused group.
:BufferGroupsPrevious          Cycle backwards in the focused group.
:BufferGroupsClose[!]          Close buffer; ! explicitly discards changes.
:BufferGroupsCloseGroup[!]     Close the focused group; ! discards changes.
:BufferGroupsCloseOthers[!]    Close other group buffers; ! discards changes.
:BufferGroupsReorder left|right Swap current buffer with adjacent group member.
:BufferGroupsReorderTo {index} Swap current buffer with group position.
:BufferGroupsToggleFullscreen  Hide/reveal the other group without closing buffers.
:BufferGroupsWinbar enable|disable|toggle
                               Enable or disable the native group winbar.
:BufferGroupsToggleTabs        Toggle tabs for the focused group.
:BufferGroupsEnable            Enable observers/configured mappings.
:BufferGroupsDisable           Disable while preserving windows and buffers.

User BufferGroupsChanged is emitted after committed changes, with event.data
{reason,tabpage}. Suitable for UI integrations; redrawtabline follows changes.

==============================================================================
BUFFERLINE AND WINBAR                                  *buffer_groups-bufferline*

Compose existing setup options, then call Bufferline setup once and attach the
adapter after setup: >lua
  local config = { options = { diagnostics = 'nvim_lsp' } }
  local adapter
  if package.loaded['buffer_groups'] then
    adapter = require('buffer_groups.integrations.bufferline')
    config = adapter.extend(config, { display = 'groups', managed_order = true })
  end
  require('bufferline').setup(config)
  if adapter and type(adapter.attach) == 'function' then adapter.attach() end
<
The adapter's default display is 'buffers', preserving the legacy grouped-
buffer view. With multiple groups, display='groups' shows group controls;
clicking one toggles only that owner group's tabs. With one group, the original
winbar is restored and all buffer tabs appear on the global tabline, regardless
of tabs_visible. Creating another group restores winbars and their visibility
preferences. Fullscreen retains two groups, including the hidden group.
External Bufferline group tabs keep normal visibility.
The adapter composes host options, filters and callbacks, follows core ownership
and cycle order, and sends clicks to the owning split. In fullscreen it hides
buffers owned by the hidden group.

With mode='buffers' and managed_order=true, the adapter orders owned buffers
by group order and wraps Bufferline's native move operations around the
group-local reorder API. The core has no Bufferline dependency. When disabled,
or for unmanaged buffers, native Bufferline move behavior is used. With the
core active, managed sorting continues when reordering.enabled=false. Disabling
the core restores host sorting and command behavior until it is enabled again.
Setting managed_order=false retains the host sorter and disables managed
sorting. Bufferline pinning and manually created groups can override the global
tabline order; those native partitions are not covered by the reorder
integration checks.
BufferGroupsReorder and BufferGroupsReorderTo change buffer order only; they do
not invoke Bufferline's sort commands. Reorder changes are session-only.

Hide the plugin's group controls with: >lua
  require('buffer_groups').setup({
    winbar = { enabled = true },
    tabline = { show_groups = false },
  })
<
With display='groups', an attached winbar and multiple groups, false omits the
plugin's group controls. The entire tabline is hidden when Bufferline's evaluated
output has no visible content apart from sidebar offsets. External buffers,
custom areas and native tabpage indicators keep it visible. Sidebar offsets,
including labels and separators, reserve layout space and do not reveal an
otherwise empty line when opening an explorer. They are preserved whenever
other content keeps the tabline visible. Whitespace/highlight/fill alone are
ignored. With one group, or a disabled winbar/plugin, normal Bufferline
behavior returns. While visibility is controlled, a 200 ms timer checks content
even when hidden, revealing asynchronous custom areas without an editor event.
The timer stops when ownership ends or rendering fails. Current Bufferline
options are resolved after colorscheme changes; each table's original native
auto-toggle setting is preserved. Visibility and auto-toggle settings are
restored when ownership ends. get_tabline_options() returns a copy of the
current settings.
The option is boolean and defaults to true; Bufferline remains optional.

The PTY test exercises Shift-Alt-H/L and lowercase Alt-h/l while observing
Bufferline's public rendered elements. A PTY cannot visually inspect the
terminal tabline or confirm key encoding through a user's terminal and
multiplexer; manually check both mappings and the two-group display there.

:BufferGroupsToggleTablineGroups toggles the group controls for this session.
Configure a shortcut with: >lua
  keymaps = { toggle_tabline_groups = '<leader>mt' }
<
The toggle affects all tabpages and changes only session state. It does not
change the configured default or save anything to disk. Disable/enable retains
the session choice; setup() or reopening Neovim restores tabline.show_groups.
API: toggle_tabline_groups() and set_tabline_groups_visible(boolean) return
true, visible (or false, error for invalid input). get_tabline_options().show_groups
reports effective visibility. Single-group buffer tabs are unaffected.

Bufferline is optional to core group management. The native group winbar needs
an attached compatible Bufferline adapter. The internal renderer contract is
validated against Bufferline 4.9.1; pin that version for this UI.
If unavailable or incompatible, the
UI disables itself and warns; core grouping continues. Setup configures the
native winbar: >lua
  require('buffer_groups').setup({
    winbar = { enabled = true, position = 'prepend',
               alignment = 'left', reveal_on_use = false },
  })
<
position accepts prepend, append, replace, or manual. alignment accepts left,
center, or right. With reveal_on_use=false, hiding persists. With true, using
a group reveals its tabs on focus, cycling, or opening a buffer. This is separate from fullscreen.
The native element owns rendering and has no styling flags. Bufferline owns its
icons and appearance. Existing window width and controls are restored safely;
Treesitter context remains below the winbar.

set_winbar_enabled(boolean) and is_winbar_enabled() control/query the winbar.
set_group_tabs_visible(boolean, opts) and toggle_group_tabs(opts) control group
visibility; opts.group_id and opts.tabpage default to the focused group and
current tabpage. State snapshots include winbar_enabled and each group's
tabs_visible value. :BufferGroupsWinbar enable|disable|toggle and
:BufferGroupsToggleTabs expose the controls. Optional keymap names toggle_winbar
and toggle_tabs are available; no local keys are installed by default.

For manual composition, require('buffer_groups.ui.winbar').render(win) returns
a native tab fragment for that window. position=manual leaves placement and
winbar ownership to the external provider. Native hover, pick and cycle commands
remain global and are not adapted in this version. Pin and manual sorting also
remain Bufferline-global. managed_order=false keeps Bufferline's native sorter.
insert_after_current and insert_at_end require it because they depend on private
render history. The UI iterates groups dynamically; the core currently manages
at most two groups. Extending that layout is a separate change.

==============================================================================
LIMITS                                                 *buffer_groups-limits*

Two managed groups only. Floating/auxiliary windows are not layout owners.
Additional manual splits stay unmanaged while partitioned. No cross-restart
persistence. No WinShift dependency or integration. Async integrations should
pass an explicit editor window to
open/register instead of inferring ownership from the focused prompt.
